# Bit-variable names could alias

The bit compiler represented an input bit by concatenating its variable name
and bit index. `v1` at bit 10 and `v11` at bit 0 both became `v110`.
The twelve-input inverse assembler exposed this ambiguity. Its consistency
assertion stopped generation before any proof was accepted.

The fix rejects variable lists whose bit symbols are not unique.
The inverse generator also uses alphabetic variable suffixes. Normal callers
keep their existing symbol names and generated bytes.

`tests/packed-bit-compiler.mjs` rejects the actual alias pair and duplicate
variables, and accepts twelve distinct alphabetic names. The fixed
`u02-packed-inverse-v1` guard reproduces the collision using the compiler from
commit `cb2ac04`. It compares all previous routing, packing and packed-move
proof bytes before reusing their evidence. The guard passed, including all
twenty-one semantic checks and six rejecting fixtures. Its source-sealed
record is `docs/verification/next-plan/U02/u02-packed-inverse-v1/index.json`.

The Bend proof checker was not bypassed. This was a generator-input ambiguity,
not evidence that a false theorem passed either checker.
