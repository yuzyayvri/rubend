# Rubend workbench redesign

Yuzy requested a from-scratch visual/UX redesign on October 22. The old hero
headline, motivational copy, lime accent, rounded card stack, and wire-cube logo
are removed. This is a local implementation, not a published release.

## Two working directions

| Direction | Structure | Decision |
| --- | --- | --- |
| Paper workbench | Warm flat surface, italic wordmark, cube field, adjacent search controls, full-width numbered notation strip | Selected. Position, search, and sequence have a clear reading order. Notation stays continuous. |
| Drawing board | Dark blue field, right-hand vertical move ledger, input/search along the bottom | Rejected. The search and playback paths feel fragmented; lower controls are cramped. |

Both prototypes ran against the preserved controller and actual native solver.
Their screenshots are visual comparisons, not acceptance of the repaired bundle.
Sources are in `docs/design/prototypes/`. The selected layout is implemented in
the production HTML/CSS, with subsequent contrast and sticker-boundary refinements.
No image generator, external font service, component framework, or new runtime
dependency is used. The cube is the actual interactive renderer, not decoration.

## Decisions in the implementation

The cube owns most of the workspace. Search is a compact adjacent instrument,
not a landing-page section. Moves are numbered rectangular notation cells.
The active/last move stays visible inside an overflowing strip without scrolling
the page away from the cube. A small pure geometry function owns that calculation.

Paper is the initial theme only when no preference exists. Stored dark mode is
honoured across reloads. Labels, buttons, empty/error/status states, dialogs,
favicon, and notation styling are rebuilt. Status copy states what happened.
There are no promises of instant optimality or complete formal certification.

The existing sixty controller targets remain. Native dialogs retain focus
handling. Face letters supplement colour. White sticker cells have visible
boundaries. The budget exposes seconds through `aria-valuetext`. Six static
theme contrast pairs exceed 4.5:1; that is not a complete accessibility audit.
The first light secondary-text pair measured 4.1466:1 and failed the static
check. Its final value is 4.7989:1. The prototype retains the earlier palette.

The same pass found a real keyboard lock bypass. During active search, three
arrow presses advanced the committed step to three while visible playback
controls were disabled. `jump()` now checks active search, like `play()` already
did. The focused actual-main test rejects the frozen source with `1 !== 0` and
passes current source. Nine keyboard scenarios pass, including queued seeks.

## Evidence and limits

[Before/prototypes](../verification/next-plan/U01/redesign-before-v1/index.json)
preserve both directions and the failing browser probe.
[Final rebuilt-browser checks](../verification/next-plan/U01/redesign-final-v1/index.json)
cover 1440×900 and 390×844 views, solve/export, canonical playback, locked search
keys, repeated seeks, rail visibility at both ends, stored dark preference, and
the 54-sticker editor with fixed centres and unchanged-position save.
All preview owners and IPC stop; tabs close and the viewport resets.

The full rebuilt regression and proof queue is pending. The native solver,
cube rules, search policy, and established twenty-three laws are unchanged.
No performance improvement is claimed. Previous profile/CI-package results
remain bound to their pre-redesign sources. The old CI artifact does not contain
this UI or the keyboard fix. Do not rewrite its receipts as current evidence.

Implementation and design comparison are solo. Independent review did not run.
Operator review of the changed interaction is still required before any
separately authorized merge. Publication and deployment are not authorized.
