# The checked reference does not certify the optimized app

The complete bounded reference is checked. The remaining U06 step is to name
the missing implications from the optimized engine to that reference, not to
rename a numeric completion flag a proof. This record does not propose or
implement a new domain law.

## Two different result contracts

`BRTResult<radius, cube>` either contains a within-radius replay-proved word or
excludes every solving word within that radius. Its checked declaration ties
the proof to the actual input and bound. It has no timeout result.

Production `Search.Meta` and `Portfolio.Session` carry U32 lower bounds and a
`Completion` constructor. Native main replay-certifies each emitted candidate.
The host independently checks replay, monotone bounds and consistency between
the incumbent length and optimal flag. These checks do not carry or establish
a universal optimized exclusion theorem.

Even a proved bounded answer need not be shortest. The actual reference on a
U root at radius two returns `[1, 0, 1]`, meaning found with moves `U U2`.
That solution is valid and within radius, but `U'` solves the same root in one
move. A successful result from that call alone cannot justify an optimal label.

## Reproducible checks

`bench/u06-refinement-checks.mjs` records each of the seven native entrypoints'
actual relative import closure, Completion constructors and metadata types.
It checks the candidate certification call and rejects three altered-source
inventories. These are source observations, not a proof of program semantics.
The reference proof archive, module and dependencies are verified by hash.
The unchanged 87-input root/toolchain gate is explicitly reused.

`tests/reference-label-boundary.mjs` calls that actual reference for all eighteen
one-move roots at radii zero, one and two. It independently replays every found
packet, retains the non-shortest counterexample, and exercises the actual export
and progress functions. Three actual export-source mutations must fail for a
false search-optimal label, an unsupported formal field and a lost proof note.
Unsolicited proof-shaped input fields must not enter the exported record.

The fixed queue is `u06-refinement-v1`, expected within one minute and capped at
two. Both jobs request 512 MiB on one low-priority CPU with the full desktop
reserve. No native rebuild, database, browser, benchmark or holdout is needed.
Results remain pending until the canonical detached-result checker passes.
Independent review is not run under the solo restriction.

## Result

The [archive](u06-refinement-v1/index.json) verifies 2,796 seals and both
resource receipts. The worker is gone, with no resource stop. The seven native
entrypoint inventories agree with their actual current source. The owned
profile's extra `ContinuationFailure` is retained, not silently dropped.
All three altered-source inventory controls and three actual export-source
mutations reject for the intended disagreement.

All 54 reference queries over eighteen one-move roots pass. Every one of the
36 found packets independently replays. The actual U/radius-two packet is
`[1, 0, 1]`, a two-move answer at a one-move optimum. The current export and
progress functions retain the incomplete interval and reject an optimal flag
whose lower bound does not meet the answer length. Unsolicited proof-shaped
fields do not appear in the exported record. The original reference proofs and
the unchanged 87-input root gate are explicitly reused, not rerun.

This finishes source-bound gap identification. It does not discharge any of
the seven missing implications, prove absence of all possible implementation
defects, or certify the optimized application. No production behavior changed.

The later [search-goal reflection](SEARCH-GOAL-REFLECTION.md) now proves that
each actual profile's positive packed solved predicate implies packed identity,
facelet solved equality and a zero-radius found result in the checked reference.
Its fully sealed finish retains the failed resource run and fixes the finite

on padding examples. This closes a positive-goal subcase only. All seven broad
implications in the table still need their remaining premises and refinements.
