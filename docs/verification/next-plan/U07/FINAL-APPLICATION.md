# Final application acceptance

Status is preparation, not passed browser acceptance. The numerical report is
verified and delivered. The October 24 completion/report/no-push order remains
binding before this last application unit. No frozen source or selected
configuration changes. No holdout solver attempt repeats.

## Existing ownership

The installed browser fixture verifies the actual imported package and confines
its native engine. The application receives SSE candidates, progress and terminal
events through `/api/solve`. Its unchanged frontend owns solution display,
playback and export. The browser's Bend model checks cube operations. Export
independently rejects a solution that does not replay. The diagnostic endpoint
only observes state.

The final campaign owns measurements and immutable per-slot results. Browser
acceptance must not become another measurement campaign. Existing installed
delivery, known-optimum, cancellation, failure and layout checks remain reusable
only with their source graph, artifact hashes and stated limitations verified.

## Usage and shape

`u07-final-app-records.mjs prepare OUTPUT` admits four saved records against the
unchanged freeze and canonical report. The records cover a hard censored default
request, preserved small and H0 controls, and a known-optimum exact request.
Each record keeps its slot, source path/hash, envelope digest, input, actor
configuration, request contract, original status and independently checked answer.

The browser fixture will consume only that prepared artifact and unchanged
installed frontend assets. It will visibly say that events are replayed and no
solver runs. Request input, mode, budget and record identity must match. Native
candidate/progress frames retain their source values. If a censored observation
lacks a native terminal frame, an explicitly labeled non-optimal fixture terminal
projection closes the UI stream. It cannot manufacture an optimality claim.
Replay wall time is not a solver measurement.

Model the Domain shapes this choice. One source-bound record contains the
measurement identity and its UI projection, rather than unrelated booleans or
hand-entered move lists. The fixture cannot send a request through a native
backend. The interface exposes record selection and ordinary app controls, not
private controller-state mutation.

## Alternatives and solo synthesis

Fresh native holdout solves would test the HTTP path directly, but duplicate
completed evaluation work and complicate the frozen resource contract. They are
rejected. Native installed-path evidence is already source-bound and passing.

Directly injecting a solution into the client would avoid a proxy, but bypass
the SSE parser and normal application state transitions. It is rejected.

Captured-event replay is selected. It exercises ordinary input, solve-response,
playback and export paths while preserving the original measured provenance.
It does not replace or claim a fresh native solve. This is a sequential solo
design comparison, not an independent or multi-model review.

## Acceptance boundaries

The final matrix must identify which lanes reuse actual installed/native evidence,
which use stored-event browser replay and which tier proposals remain unselected
or unsupported. Optional benchmark profiles are not additional solver families
or a newly shipped GUI profile selector. The larger exact-tier requirement must
not be declared passed by relabeling a fast H0 control as an exact configuration.

Final U07 acceptance remains open until observations, screenshots, exported
answers, source reuse and cleanup have executable evidence. Browser CPU/memory
are not claimed bounded by the local server's cgroup. The preview stays hidden.
Operator review and any push or merge remain later user decisions.

The first implementation step prepares source-bound records and rejects altered
record controls in a fixed low-priority queue before browser work.

The local bounded preflight admits all four records, rechecks the installed
package assets and prior screenshot hashes, and passes 28 altered-record or
request controls. No solver executes. These are data-admission tests, not browser
acceptance. The source-bound `u07-final-app-data-v1` queue follows the signed
implementation checkpoint with two serial one-GiB CPU2 jobs and a five-minute
queue cap. Canonical verification precedes further tracked edits and browser use.
