# Small-product conditional information

The audited EP4 by corner-class table adds information over its separate
components. That does not establish value over the existing phase-two bounds.
This screen compares it with the actual CP-by-middle and EP8-by-middle pipeline.

Reuse the audited 235,200 distances. Serialize those exact words to a new
940,800-byte file and verify every word against the native source record.
The existing bounded cache loader reads the file into an owned array. No small
product distances are regenerated. Normal application initialization constructs
the unchanged Light tables. The new files stay under `build` and out of Git.

The native probe constructs 64 fixed 32-move restricted-walk roots and their
640 children. For each root, it scans parent radii 1–14 and history codes 0–9
through the real `Search.node_open` function. The 8,960 contexts exercise the
existing predecessor, root-mask, coordinate-transition, and two-bound filters.
The probe records the exact admitted move mask for every context.

An independent host permutation ranker checks the recorded existing coordinates.
The already audited product backend checks each new index and cached distance.
The scorer reconstructs the existing admission masks before counting any extra
exclusion. A child has residual depth `parentRadius-1`. Its product distance cuts
only when it is at least the positive parent radius. Zero radius and unknown
distances are refused. Tests cover equality at this boundary.

Actual wrong-bound-offset and wrong-product-index source variants must fail
reconciliation. A truncated word file must be rejected by the real cache loader.
Record controls cover missing, duplicate, unknown, out-of-range, stale-context,
goal/profile, and move-mask changes. Existing proof and toolchain gates stay
unchanged. No new domain law is introduced.

These are synthetic radius/history contexts on fixed roots, not a trace of how
often a real portfolio reaches those contexts. Counts are not independent solve
trials or saved traversal steps. Even a positive result needs measured lookup
cost and whole-search correctness/quality evidence. A zero result does not reject
the complete EP8 product. No production pruning, solver speedup, new default,
release case, publication, or independent review is included.

The fixed queue is `u04-small-conditional-v1`, expected three minutes with a
ten-minute hard cap. Compile/proof jobs use at most 3 GiB and four low-priority
lanes. Native observations and scoring run serially on CPU2 under 1 GiB.

## Result

The queue passed. Canonical verification checks 2,539 seals and three resource
receipts, with the worker gone and no resource stop. The
[archive](u04-small-conditional-v1/index.json) retains all native observations.
All 640 child facts and 8,960 admission masks reconcile. The 64 roots are distinct.
The two actual source corruptions fail for the expected mask/index mismatches.
The malformed cache, sixteen record corruptions, thirty residual-boundary checks,
and unchanged proof/toolchain gates pass. Distances are reused, not regenerated.

The scorer finds 376 hypothetical exclusions among 23,932 admitted children,
across twenty roots. They occur at parent radii seven through nine. There are
6,305 admitted children within the table's ten-move support, so the earlier
small-edge radius mismatch does not apply to this screen. Fifty of the 640
child rows have a product distance above the existing bound maximum.

The disposition is `extra-exclusion-in-synthetic-contexts`. Repeated radius and
history combinations are not independent cubes or actual search visits. No
saved work, CPU benefit, solution-quality gain, or pruning integration follows.
