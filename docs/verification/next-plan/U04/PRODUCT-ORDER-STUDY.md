# Product-informed portfolio experiment

The product-order preflight passes. This experiment asks whether sibling order
improves returned solution length, coverage or exact progress at fixed work.
The proposed claim is a repeatable fixed-work improvement on the frozen
development cases, not a general speedup. No gain is assumed.

One native binary runs the unchanged portfolio on arms zero and two and the
private product-ordered portfolio on arm one. It reuses the checked bounded
portfolio wrapper, candidate certificates, record protocol, scorer and controls.
One ordinary Light array holds base tables, reused product words and maps across
all requests. Every arm pays the same setup. The ordinary profile is not the
current packed-small application profile, so this is not application acceptance.

Freeze development roots 536 through 543 before execution. These are distinct
from the prior move-order study and the product-information pilot. Both request
modes run at 160,000 and 640,000 Search.advance calls through five alternating
three-arm cohorts. All 480 requests remain in the denominator. The shallow,
zero, one-step and partial-quantum guards run first. Independent replay checks
every returned candidate. A running result must consume its declared work.
Exact completion must retain its actual status and matching bound.

The frozen acceptance rule requires a gain in the same root, mode and budget
in all five cohorts, with no paired coverage, length or lower-bound loss anywhere.
The two identical arms must match, as must repeated semantics. A failed floor
rejects the treatment. No repeatable gain leaves it unconfirmed. Both outcomes
skip long cost and profile work. Repeating the same eight roots does not supply
forty independent inputs.

Only a qualifying fixed-work result opens the fixed 60-request cost phase.
Roots 536 through 539 use fast mode and eight million steps in five alternating
cohorts. Warm native wall includes portfolio setup, ordering, certificate output
and timer calls. Table generation, product load, map fill and host validation
finish before request timestamps. Final point and terminal record printing after
the last timestamp are excluded. These are not process CPU or app latency.
Samples must clear 100 ms. Identical-arm spread must stay within five percent,
and first-answer p95 must not regress by more than five percent. Small or noisy
records cannot establish a timing gain. Keep medians, ranges, errors and timeouts.

A separate instrumented executable profiles roots 536 and 537 on each policy
after timing. Its times are excluded. A profile must identify the actual limiter
before any performance conclusion. A fixed-work gain still needs native deadline
and application confirmation before promotion.

`bench/generate-product-order-study.mjs` derives the worker and runner from the
existing checked templates with exact replacement-count assertions. It changes
the candidate Search import, matched table preparation, request file arguments,
and frozen development selection. The scorer and budgets are unchanged. New
wrapper definitions receive a fresh verdict. The 87-input root gate and cursor
and product preflights are reused only after identity checks.

The queue is `u04-product-study-v1`. Expected eight minutes, capped at 25 minutes.
Builds use at most 3 GiB and four low-priority lanes. Guard and scored phases
use CPU2 and 2 GiB. No overlapping benchmark, browser, new distance BFS,
large table, domain law, production change, release holdout, publication or
independent review is included. Product ordering changes no pruning rule.

## Result

The [canonical archive](u04-product-study-v1/index.json) verifies 2,952 source
seals and six receipts. The worker is gone and no resource stop occurred.
All 168 guard requests and 480 fixed-work requests pass protocol and work checks.
Independent replay checks 90 guard and 180 quality candidate events.
Quality requests execute 192,000,000 Search.advance calls. The identical control
arms and repeated semantics agree.

All 160 paired comparisons tie on final length and lower bound. There are zero
repeatable quality wins and zero losses on these declared budgets. The frozen
disposition is `unconfirmed-fixed-work-benefit`. Long-cost and instrumented
profile jobs record skips, not timing measurements. Do not rerun these same
cases unchanged to seek a win.

The generated wrapper passes a fresh verdict and owned-array checks. Unchanged
product, cursor and root evidence is explicitly reused. Keep the treatment
private and unpromoted. This result does not prove a CPU regression or rule out
benefit at other budgets. No production, exact inference or holdout changed.
