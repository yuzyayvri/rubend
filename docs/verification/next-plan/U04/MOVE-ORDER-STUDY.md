# Isolated phase-two ordering study

The finite preflight passes. This experiment tests whether the ordering policy
earns a later native-deadline trial. It does not integrate the policy or change
the default. Only restricted Subgroup child order differs.

One binary contains the original portfolio and a source-isolated portfolio whose
Search import points to the verified ordered module. Arms0and2 call the same
original implementation. Arm1 calls the ordered implementation. Reuse the actual
bounded-portfolio wrapper to preserve20,000/60,000-step quanta and truncate only
the final quantum at the declared total Search.advance budget. One ordinary
Light table is owned across requests. No new distance database or raw-cache read.

Freeze development roots528through535 before execution. These are disjoint from
the earlier512–527premoving experiments. Run both request modes at160,000and
640,000work steps through five alternating three-arm cohorts. All480planned
requests remain in the denominator. Zero, one-step, partial-quantum and shallow
convention cases run first. A sample is not independent merely because it repeats
the same root. No release file is used as a solve input.

Every candidate passes the real Bend replay certificate and independent host
replay. Native points record candidate availability after certificate/output work.
Require monotone incumbents, lower bounds, counters and clocks. A running result
must consume its full work budget. A terminal result must retain its actual
status. Never call a fuel limit successful completion. Preserve all raw records.

The primary test is fixed-work quality. Require a gain on at least one
root/mode/budget in all five cohorts, with no paired coverage, length or lower-
bound loss anywhere. A/A quality must be identical. Otherwise preserve the
rejection or unconfirmed result and skip longer work under the frozen rule.
Five repeats do not turn this study into a release-quality estimate.

Only a qualifying fixed-work result runs the separate cost stage. Freeze roots
528–531in fast mode at8,000,000steps, five alternating three-arm cohorts. Request
time includes portfolio initialization, all ordering work, certificate/output
work and timer calls. Table initialization and host input validation are excluded.
The timestamp follows candidate output. Final point and terminal JSON printing
after that timestamp are excluded. Integer-millisecond clock resolution stays
explicit; tiny first-answer differences are not a latency gain.
These are warm native wall times, not process CPU or application latency.
Require samples of at least100ms, A/A variation at most5percent and first-answer
p95 no worse than5percent before describing any timing signal. Keep count,
median and range per root and arm. Do not promote a kernel speedup from this.

A separate instrumented executable profiles the frozen roots528and529in each
arm after cost measurements. Its times never enter the scored samples. Preserve
the C source, compile flags, profiler records and symbol/line report. The profile
must identify the actual limiter before a performance conclusion.

Compare complete records, not successful answers alone. Keep failed, missing,
duplicate, partial, replay-invalid and metadata-drift controls. The accepted app,
23laws and sealed preflight remain unchanged. An apparent fixed-work gain still
needs fresh deadline and real-application confirmation. Independent review is not
run under solo work. No new pruning law, publication or deployment is included.

The fixed batch is `u04-move-study-v1`, expected eight minutes with a25-minute
cap. Compilation uses3GiB and up to four low-priority lanes. Scored worker jobs
use2GiB andCPU2, one search thread. The separately instrumented stage may use
3GiB on the same lane. It is skipped with long-cost work unless the frozen
quality gate passes. No overlapping build, browser or benchmark runs.

## Result

The [canonical archive](u04-move-study-v1/index.json) verifies2,422source seals
and six resource receipts. The worker is gone and no resource stop occurred.
All168guard requests and480fresh fixed-work requests pass protocol/work checks.
Independent replay checks285candidate events. The quality run accounts for
192,000,000Search.advance calls. Both A/A semantics and repeated states are stable.

All160control/treatment pairs tie on final length and lower bound. There are
no repeatable quality wins and no quality losses on the declared budgets.
The disposition is `unconfirmed-fixed-work-benefit`. The frozen rule skips
longer cost and profile runs. Their passing skip receipts are not measurements.
The wrapper kernel and unchanged proof/toolchain gates pass.

Keep the policy private and unpromoted. This result does not establish a CPU
regression or benefit at other budgets, on other roots or at application deadlines.
Do not rerun these same cases unchanged to seek a win.
