# Product-informed phase-two sibling ordering

The audited EP4 and corner-class product has information that the existing
small phase-two bounds miss on recorded search entries. Its mapped probe has
finite correctness evidence. Helper timing remains inconclusive. Neither fact
establishes a whole-solver benefit.

This private treatment uses the product only to order siblings. Every phase-two
column remains in the existing three-bucket cursor. Existing canonical filters
and bound guards still decide admission. Reduction and FullCube keep their
original ordinal traversal. No product value becomes an exact lower bound or
a new pruning rule.

The existing ordinary Light array has 8,388,608 words. Its normal tables end
before index 4,923,465. The treatment reuses the audited 235,200 product words
at 5,242,880. CP and EP8 maps occupy 40,320 words each at 5,505,024 and 5,570,560.
All regions are disjoint. No distance generation or additional array is needed.
Map initialization checks geometry. Unknown distances and invalid map values
yield score zero, which still retains the child.

Two alternative shapes were rejected in this solo design pass. Direct product
pruning would require additional inference and refinement acceptance. Sorting
again at every child selection would repeat probes. The selected design reuses
the already checked prepared cursor and collects ten product scores once per
node. There is no frame-layout change or compatibility path. This is not an
independent design review.

`bench/generate-product-order.mjs` first reproduces the existing ordering
variant, then changes only its score collector. Source-count assertions refuse
unexpected templates. The generated private Search is never imported by the
application. The preflight checks actual child-set equality on 4,800 combinations
of roots, goals, radii and previous-face codes. All 160 native child scores
must equal direct packed-cube projection into the audited distances.
An actual goal-routing mutation must change child sets outside Subgroup.
Independent permutation, placement and parity checks cover all 80,640 maps,
and saved real phase-two entries check product indexes and distances.
Actual map and distance source mutations need counterexamples.

The unchanged cursor's exhaustive coverage, tie and resume checks are reused
from `u04-move-v2`. Its source and archived evidence must match. The unchanged
23-law and toolchain gate is reused across the same 87 inputs. Changed pure
definitions and generated Search receive fresh BendTT verdicts. Ordinary native
initialization and emitted owned-array mode are checked.

The fixed preflight is `u04-product-order-v1`, estimated four minutes with a
twelve-minute cap. Builds use four low-priority lanes and at most 3 GiB.
The native and finite checks use CPU2 and at most 1 GiB. Existing product bytes
and observations are reused. No timing comparison, production promotion,
new domain law, large build, holdout, publication or independent review is included.
Actual fixed-budget search quality and cost are the next gate after this
preflight passes. No performance gain is claimed.

## Result

The [canonical archive](u04-product-order-v1/index.json) verifies 2,913 source
seals and three receipts. The worker is gone and no resource stop occurred.
All 4,800 native child-set cases and 160 native direct-product score checks pass.
The actual goal-routing fault produces 3,200 child-set counterexamples.
All 80,640 independent map entries and 15,609 saved actual queries agree.
The finite score and cursor checks pass 640 and 896 cases respectively.
Among those synthetic cursor cases, 246 change order. All columns remain present.
Twelve fallback controls and three actual helper-source mutations pass.
Existing table contents and product words are preserved.

The changed helper and generated Search pass fresh BendTT verdicts. The unchanged
cursor coverage and 87-input root gate are explicitly reused, not rerun.
Keep the variant private. No whole-search quality or performance acceptance follows
from this preflight.
