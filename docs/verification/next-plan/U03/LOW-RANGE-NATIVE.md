# Small edge bounds on actual low-radius prefixes

The old information screen sampled remaining radii 7–13. The small reference
distances never exceed six, so its zero hypothetical cuts were guaranteed.
That result stays inconclusive. This is a separate, deliberately narrow screen
where actual residual radii can overlap the candidate information.

The profile is the unchanged packed-small `Light` source, not raw inverse-three.
Twenty-four distinct positions have independent optimum three and are generated
by the current ten phase-two moves. Selection is balanced over those generators
and never consults a candidate estimate. A complete independent depth-three
oracle checks the cases. U06's checked unpruned reference also excludes every
radius-two solution before native observation. Each incumbent is replayed and
certified by the native Bend certificate boundary.

## Actual unchanged traversal

The native worker initializes the ordinary current small table once and passes
that single owned array serially through all control and observed cases. This
is normal base-profile startup, not a new candidate PDB build. The six audited
one-, two- and three-edge reference payloads and existing codec are reused.

The control calls `SmallSearch.run`. The observer calls the same actual advance
once per requested work unit and records fresh positive-radius, non-root,
unsolved `FullCube` entries. Snapshots at work 0, 1, 100 and 5,000 compare every
metadata and frame field. The work-one checkpoint is before completion, so a
double advance cannot be hidden by both sides eventually finishing.

Each point carries its actual cube, cached coordinates, residual radius,
predecessor, cursor, path length, contour, incumbent length, goal, stage,
profile, status and reversed path. Independent facelet replay must reach that
cube from the original root. Coordinates and cube validation must agree.
Every checkpoint's seeded incumbent is independently replayed. Counts, work
ranges, record order and duplicate points are checked. A table checksum is a
canary alongside a read-only search-source guard, not a cryptographic data audit.

## What the numbers mean

After the native run, the existing projected reference bounds and conservative
decodes are evaluated offline. Projection ranks have a separate implementation.
Policies combine bounds by maximum, never sum. A hypothetical cut has estimate
strictly greater than the child's remaining radius, after that child was admitted
by the current policy. Counts name opportunities on recorded prefixes, not saved
subtrees, native probe cost or CPU savings.

These are short structured roots, with supplied optimum-three incumbents.
They do not measure first-answer quality, uniform-state strength, whole-portfolio
frequency or a larger six-edge database. The old raw-profile screen and this
small-profile screen must not be combined as a controlled speed comparison.
The range guard still requires actual discriminatory support, not just visits.

The [archive](u03-low-range-v1/index.json) verifies 2,791 source seals and all
three resource receipts. The worker is gone, with no resource stop. All
17,496 filter cases, three actual collector faults and eight altered-record
controls pass. The original root/toolchain gate is explicitly reused across
87 unchanged inputs, not freshly executed.

All 24 independently optimum-three roots pass U06's radius-two exclusion.
The native control and observer agree at all 192 checkpoints. Their seeded
incumbents replay at every checkpoint. Independent checks cover 564 positions,
2,520 projection ranks and 5,880 conservative lookups. The projection checksum
is 3,066,005,401. Each side completes after 461 actual advance calls on 22 roots
and 323 on the other two. The 5,000-work request is a ceiling, not executed work
after completion.

There are 420 eligible fresh FullCube entries, all at residual radius one.
The maximum of the two exact one-edge references would cut 225 entries.
The two-edge maximum would cut 409, and the three-edge maximum would cut 420.
Conservative three-edge decoding at bases zero and one also retains 420 cuts.
At base two it retains 414, and at bases four through six it retains 413.
The complete policy counts and raw native records are in the archived
observation. Policies still use maximum, never addition.

This establishes range overlap on actual unchanged shallow traversal.
It does not establish that a native probe pays for itself. Entry counts do not
measure descendants skipped, CPU saved or independent roots solved faster.
Supplied optimum-three incumbents and subgroup-generated roots limit the
inference. This result neither replaces the older raw-profile evidence nor
predicts a large six-edge table's benefit. Production, NP04/NP05, final holdout
and independent-review gates remain closed.
