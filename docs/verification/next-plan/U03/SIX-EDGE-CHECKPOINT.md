# Six-edge checkpoint and shallow-generation pilot

The October 25 grant authorizes the local generation and audits. This batch
implements the missing six-edge checkpoint boundary and measures an actual
partial build. It does not request another permission or promote a bound.
The original four-edge modules and their sealed evidence remain unchanged.

## Concrete geometry and ownership

The two label sets are `[0,2,4,6,8,10]` and `[1,3,5,7,9,11]`, with goal ranks
399,936 and 4,307,008. Each has 42,577,920 logical entries and a 67,108,864-cell
unboxed U32 array. A logical checkpoint is 170,311,680 U32LE bytes, transported
in 650 existing IO chunks. Array payload is 268,435,456 bytes, not an RSS claim.

`six-edge-geometry.bend` owns those native constants. The new pure admission
module checks actual capacity on both seed and resume, valid goal/range/depth,
every logical entry, unique zero, and exact reached/earlier-layer counters.
The native wrapper resumes exactly one actual existing Bend BFS layer per
fresh owner. It closes the input before search and writes a new immutable
output. Existing nonempty outputs are refused. Build metadata, payloads,
manifests, measurements and results have separate paths.

The manifest pins count, labels, goal, geometry, source and binary identities,
payload bytes/hash, counters, parent and caller-supplied expected digest.
Failed or unadmitted files have no accepted manifest and are never resumed.
Repeated successful input must produce identical payload bytes and counters.

## Fixed bounded evidence

Each pattern has four checkpoints, seed through depth three. All eight payloads
are checked word by word against an independent shallow BFS using pinned
cubing 0.66.0 KPuzzle moves and available-list partial-permutation ranking.
No full six-edge distance vector is constructed by the host oracle. Unknown
cells must remain 255. This is not a complete graph audit or NP05 proof.

Native controls cover invalid action/pattern/seed origin, actual half-capacity
seed and load, depth/counter/goal mismatch, malformed distance, short input,
read-close failure on both patterns, and native append refusal. A deliberately
weakened actual admission accepts a wrong reached count; the independent
whole-payload/counter check must reject its output. Twelve manifest/schema
controls check geometry, labels, pins and completion status. One real restart
repeat checks identical results. Failure outputs and command records remain.

Whole native-command GNU Time records include allocation, IO, admission and
an optional BFS layer. Keep failed controls distinct. Their maximum RSS is
not the resource runner's host-inclusive aggregate tree peak. This is one
planning run, not a speed comparison or a full-generation/audit ETA.

At most twelve raw files are retained, capped at 2,043,740,160 bytes plus a
2-GiB free-disk reserve. The expected main workflow has eight 170,311,680-byte
files. Repeat and corruption/fault artifacts are accounted separately.
All measurements, counters, manifests, identities and cleanup remain in raw
evidence; large payloads and binaries stay ignored.

The fixed queue is `u03-six-checkpoint-v1`, expected four minutes and capped
at twenty-five. Compile uses 1.5 GiB and four nice-10 lanes. The independent
oracle uses 512 MiB on CPU2. The serial pilot uses 3 GiB on CPU2 with a
fifteen-minute job ceiling. Confirmation uses 512 MiB. The existing desktop
reserve, no swap, aggregate RSS and memory-pressure backstops remain active.
The source-identical four-edge builder/coordinate, root87 gate and CPU observer
are reused. No browser, final holdout, competitor setup, publishing or new
foreign effects are involved. Independent review is not run.

Deeper generation requires successful engineering admission from actual pilot
costs and checkpoint behavior. It is already authorized. Complete data and
projection audits, NP05 and concrete refinement still precede any production
pruning or stronger result label.

## Verified pilot result

The [canonical archive](u03-six-checkpoint-v1/index.json) verifies 3,467 source
seals and four resource receipts. The worker is gone, and no resource stop
occurred. All eight checkpoints, six fresh-process restarts, one repeat,
fifteen native/counter controls and twelve header controls pass. Both deliberate
read-close failures clean up without output. The actual half-capacity allocator
is refused on seed and load. Native append and host existing-output refusals
leave the original payload unchanged.

The independent shallow oracle has layer counts 1, 18, 229 and 2,804 for both
patterns, totaling 3,052 reached states at depth three. Every word of each
170,311,680-byte checkpoint agrees. Including the repeat, 383,201,280 word
comparisons pass. The weakened native counter admission accepts a reached
count of twenty where nineteen cells are known; the independent full scan
rejects it. Its payload is identical to the correct depth-one data, confirming
that data bytes alone do not validate a completion record.

The depth-three payload hashes are
`1a6774caa14f838945e52f251249522e700537d39853ebd4963c7f79cb204185`
and `e7814af7c33633847ed6acd6ddedcaeb2c200862cd8172f53b1e0d981d1ce3cd`.
All twelve raw files remain ignored, totaling 1,873,428,483 bytes including
repeat and malformed/fault fixtures. Accepted manifests and raw command
measurements are embedded in the archived report.

The twenty-four native commands consume 44.16 s CPU in this single planning
run, including failures and controls. Native maximum RSS is 271,412 KiB.
The outer host-inclusive job takes 74.478 s and peaks at 758,092 KiB tree RSS.
These scopes differ. The main eight seed/layer commands consume 26.27 s CPU.
No full-generation ETA or speed comparison follows from these shallow costs.

Fresh pure admission and emitted owned-array checks pass. Existing coordinate,
four-edge and root87 evidence is reused unchanged. This establishes an actual
six-edge checkpoint boundary and checked shallow continuation, not complete
tables, full graph validity, NP05 or production admissibility. Next continue
the pinned checkpoints in bounded build batches and audit the complete data.
