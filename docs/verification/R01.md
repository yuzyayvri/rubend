# R01 progress

R01a adds frozen pilot/development/release inputs and coverage-first scoring.
It does not change the solver, claim a speed gain, or complete the full R01 unit.
The user required solo work after one read-only design candidate returned.
No independent implementation review ran. That gate is not claimed closed.

The three corpora contain 128, 1,000, and 10,000 mutually disjoint legal-state
strings generated from separate recorded seeds. Their manifests retain sampler
and model provenance plus byte hashes. The generator refuses overwriting files.
The 1,128 pilot/development states pass legality, orientation, parity, and
roundtrip checks. The release set has only identity/count/disjointness checks.
It has not been solved, scored for strength, or used to tune the engine.

The scorecard preserves all planned cases. It separates answer coverage from
conditional mean lengths, retains each paired coverage/length/lower-bound loss,
and includes incomplete exact jobs at the common time cutoff. Excess over an
optimum uses only the explicitly identified, provenance-tagged oracle subset.
Invalid replay, false optimal labels, changed inputs, regressing trajectories,
missing/duplicate cases, and host emergency completion fail closed.

Six positive scenario families and twenty rejecting fixtures pass. Re-scoring
the sealed historical warm record reproduces 160 fast, fifteen exact, and five
Superflip paired ties, with no errors. Its fast mean is still 18.75. This is
analysis of existing data, not another benchmark or evidence of a speed gain.
All sixteen existing toolchain/proof checks pass. The raw receipts and source
hashes are in r01-v1/scoring-checks.json and historical-scorecard.json.

## Explicit profile stage

Search metadata now carries a Light, RawJoint, or BlockJoint profile selected by
the checked loader entrypoint. Initializers check storage geometry once and
reject mismatches. Joint pruning dispatches on the explicit profile, not array
capacity. Existing numeric goal/completion conventions are not yet replaced.
The single owned array and all distance values remain unchanged.

Native and generated-JavaScript profile checks pass. Baseline/current fixed-work
snapshots match byte for byte for fourteen mixed light cases and fourteen raw
cases at six slices, with 98 snapshots per comparison. All 163 shallow raw
optima then match at 24 slices, across 4,075 snapshots and 3,911 candidates.
An earlier six-slice shallow attempt failed in the untouched baseline because
it had not established an optimum yet. The same longer cut was then used for
both sides. The validator and optimum assertion were not weakened.

The raw comparisons use one nice-10 core, a six-GiB ceiling, no swap, and a
240-second wall cap. The 24-slice comparison took 8.384 seconds and peaked at
2,304,944 KiB process-tree RSS. These are resource receipts, not solve-speed
measurements. Pure PROOF and BendTT checks pass. Runtime benchmark entrypoints
import foreign IO and are compiled normally, not treated as pure proof roots.
See r01-v1/explicit-profiles.json for command/output, seals, and snapshot hashes.
Matched-budget overhead and the rest of R01 remain open. No speed gain or
independent review is claimed.

## Named goal and completion stage

Reduction, subgroup solving, and full-cube solving now use distinct Goal
constructors. Search Stage, Completion, and portfolio Request also use named
constructors. External numeric fields and fixed-work records use explicit
codecs and remain unchanged. Reduction membership still launches phase two at
the original leaf rather than recording a solution.

The compiler rejects a numeric goal with the specific disagreement expected
S.Goal versus observed U32. Native and generated-JS domain/codec checks pass.
The untouched baseline and current traversal still match all 98 mixed light
snapshots and all 4,075 shallow raw snapshots, including 163 optima and 3,911
candidate records. All sixteen toolchain/proof checks pass. This is behavior
preservation evidence, not a new completeness theorem or performance claim.
The raw command/output, source/build identities, resource limits, and snapshot
hashes are in r01-v1/domain-types.json. Diagnostic attribution and timed
overhead/quality comparisons remain open, as does independent review.
