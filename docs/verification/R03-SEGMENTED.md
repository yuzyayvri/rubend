# Segmented raw foundation

The isolated segmented owner passes complete data and fixed-work checks.
Performance, deadline quality, broad app integration, and independent review
remain open. It is not a promoted memory tier yet.

The direct reader fills a 2^28-word lower block and a 2^24-word upper block
through one file handle, then keeps the generated 2^23-word prefix in its final
owner. It never first allocates the old two-GiB array. Logical addresses and raw
nibble values are unchanged. All 285,525,248 used words match the old loader,
including the complete prefix and all 277,136,640 raw words.

All 4,075 shallow and 350 general fixed-work snapshots equal the frozen typed
reference. No cube, path, coordinate, bound, completion, or work field is masked.
The shallow comparison includes all 163 known optima and 3,911 candidates.
Five malformed file/fingerprint cases, boundary routing, wrong dimensions,
and unsupported profiles pass. The zero-geometry collision described in
[the closed prototype issue](../issues/segmented-zero-geometry.md) fails before
and passes after the fix. Full word and fixed-state comparisons are rerun.

The pure owner, reader, search, and portfolio pass the unchanged twenty-three-law
BendTT gate. This is not a universal layout/refinement theorem. The runtime word
reader remains outside the pure graph. The shared timer builder now routes this
owner through the same frozen 500-slice template as its control. Its native
build and existing source-snapshot rejection fixtures pass.

The [archive index](r03-segmented-foundation-v1/index.json) binds sources, frozen
binaries, raw receipts, malformed inputs, and complete snapshots. The large
pretty snapshot records are losslessly minified into separate files before
compression. Object equality and both original/compact hashes are retained;
the originals are not overwritten. The original joint cache remains mode 0644
and its full SHA-256 is read back unchanged.

The 1,120-MiB physical allocation is arithmetic, not observed RSS. Compare fresh
native ready/after-search RSS, initialization, fixed-work CPU, and deadline
quality before deciding whether to retain this tier. Keep rejected outcomes
and the existing default unchanged until those gates are decided.
