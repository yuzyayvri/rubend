# Segmented raw foundation

The isolated segmented owner passes complete data and fixed-work checks.
The five-cohort measurement rejects promotion. Broad app integration and
independent review remain open. It stays an isolated research profile.

The direct reader fills a 2^28-word lower block and a 2^24-word upper block
through one file handle, then keeps the generated 2^23-word prefix in its final
owner. It never first allocates the old two-GiB array. Logical addresses and raw
nibble values are unchanged. All 285,525,248 used words match the old loader,
including the complete prefix and all 277,136,640 raw words.

All 4,075 shallow and 350 general fixed-work snapshots equal the frozen typed
reference. No cube, path, coordinate, bound, completion, or work field is masked.
The shallow comparison includes all 163 known optima and 3,911 candidates.
Five malformed file/fingerprint cases, boundary routing, wrong dimensions,
and unsupported profiles pass. The zero-geometry collision described in
[the closed prototype issue](../issues/segmented-zero-geometry.md) fails before
and passes after the fix. Full word and fixed-state comparisons are rerun.

The pure owner, reader, search, and portfolio pass the unchanged twenty-three-law
BendTT gate. This is not a universal layout/refinement theorem. The runtime word
reader remains outside the pure graph. The shared timer builder now routes this
owner through the same frozen 500-slice template as its control. Its native
build and existing source-snapshot rejection fixtures pass.

The [archive index](r03-segmented-foundation-v1/index.json) binds sources, frozen
binaries, raw receipts, malformed inputs, and complete snapshots. The large
pretty snapshot records are losslessly minified into separate files before
compression. Object equality and both original/compact hashes are retained;
the originals are not overwritten. The original joint cache remains mode 0644
and its full SHA-256 is read back unchanged.

## Measured disposition

Five alternating fresh cohorts observe native peak RSS of 1,159,136 KiB against
2,142,148 KiB for the frozen typed raw control. Each cohort has the same peaks.
The 45.9 percent reduction passes the memory target. Warm-file initialization
medians are 1,398.6 ms and 1,835.6 ms, respectively. Their ranges are 1,352.9 to
1,468.6 ms and 1,806.6 to 1,915.4 ms. These are not cold-disk measurements.

The equal-work run passes all 1,630 shallow warmups and 110 measured jobs.
Every complete native state agrees. Five-cohort geometric CPU ratios are
1.1088 for fast work and 1.0585 for exact work. The cohort-bootstrap 95 percent
intervals are 1.0988 to 1.1193 and 1.0398 to 1.0814. Neither passes the declared
five-percent overhead gate. The emitted owner dispatch is a possible cause,
not a profiled explanation. No general speed verdict or speed promotion follows.

The application run passes all 1,750 jobs without errors, missing answers, or
forced cleanup. All sixty deadline answer lengths tie. However, three of five
Superflip intervals have a weaker lower bound. The unchanged scorecard therefore
rejects the quality floor. Answer lengths alone would hide that loss. The layout
is not promoted, even as an accepted memory tier. The existing default stays.

Both runs use CPU 2, nice 10, a 6,144-MiB cap, and a ten-minute batch cap.
Their resource receipts pass. All ten native workers shut down and remove IPC.
There are no concurrent builds during either measurement. Desktop activity is
uncontrolled, so the five alternating cohorts limit, rather than remove, noise.

The [measurement archive](r03-segmented-measurement-v1/fixed-time.json.gz) keeps
every equal-work observation. Its [resource receipt](r03-segmented-measurement-v1/fixed-time-resource.json.gz)
is separate. The [deadline resource record](r03-segmented-measurement-v1/deadline-resource.json.gz)
contains the complete report, source seals, configurations, RSS samples, native
events, and cleanup. The [CPU adjudication](r03-segmented-measurement-v1/time-score.json.gz)
and [deadline scorecard](r03-segmented-measurement-v1/quality-score.json.gz) record
their input hashes. Every archive is exclusively created and roundtrip checked.

Reproduce adjudication with `node bench/summarize-fixed-time.mjs` on the first
archive and `node bench/score-warm.mjs` on the deadline resource archive.
These commands accept gzip inputs. No sealed input or baseline is overwritten.
